# 酒店场景演示包

一份能让知微从"聊天"变成"交活"的输入材料：一家虚构连锁门店（景岸·杭州钱江世纪城店）
2026 年 10 月的经营数据、总部品质督查通报、店长月度述职要求，以及三段可以直接粘进
对话框的派工文案。

品牌、门店、数据、客人点评**全部虚构**，不对应任何真实经营数据，也不取自任何真实酒店集团。

## 复现步骤

1. 装好知微并配好模型服务（见根目录 README 的快速上手）。
2. 新建项目群，把项目的目录指向本文件夹（`demo/hotel`），成员加三个岗位：
   文档撰写（`writer`）、数据分析（`da`）、bug 测试（`qa`）——项目经理会自动在场。
3. 打开 [`00-这个月要交的三件活.md`](./00-这个月要交的三件活.md)，把「派工 1」整段粘进对话框。
4. 等审批卡出现后确认。之后你会看到三条真实动作，而不是演示台词：
   项目经理拆单 → 数据分析先在沙箱里装 `python-pptx` 等生成库、算数、生成文件 →
   交付后项目经理不签收，先把质检单派给测试岗 → 测试岗跑质检规格里的 15 条断言 →
   不合格就下发返工单，返工后复测。
5. 三条派工依次跑完，工作目录里会有三个文件：
   `店长月度述职_2026年10月.pptx`、`品质督办整改报告_2026年10月.docx`、
   `10月经营分析_成本与渠道拆解.xlsx`。都能在 Office 里选中改字，不是截图。

## 数据是刻意留了破绽的

底表里 GOP 率 40.04%，预算要求 42%。差的 2 个百分点拆得到具体成本项，但**底表没有给现成答案**。
这就是质检环节能真打回的原因：派工文案要求"算到具体成本项和金额"，糊弄不过去——
写"加强管理"这类空话会被断言判不合格，数字对不上也会被拦下。

三份质检规格里内嵌的是可运行脚本，落盘即执行，不依赖任何外部 Office 二进制。
菜谱本身在 [`../../skills/system`](../../skills/system)。

## 重新生成底表

`素材/10月经营数据底表.xlsx` 由脚本生成，改了口径就跑一次：

```bash
python3 脚本/make_hotel_base_table.py
```

它只依赖 `openpyxl`，会把 31 天日明细、渠道结构、成本与 GOP、预算与同期对比、客评与品质
五张表写回 `素材/`，并且自带守恒断言（渠道间夜与营收必须加总回门店口径，对不上直接报错）。

## 文件

| 文件 | 用途 |
| --- | --- |
| `素材/00-门店基础信息与经营口径.md` | 口径定义：可售房、OCC/ADR/RevPAR/GOP 怎么算，哪些数字不许自己造 |
| `素材/01-总部品质督查通报-2026年10月.md` | 派工 2 的输入：12 项问题清单 + 集团对整改报告的三项硬要求 |
| `素材/02-店长月度述职要求-2026年11月场次.md` | 派工 1 的输入：六个必答问题和页数上限 |
| `素材/10月经营数据底表.xlsx` | 三件活共同的数字来源 |
| `脚本/make_hotel_base_table.py` | 底表生成器，唯一的数字来源 |
| `00-这个月要交的三件活.md` | 三段派工文案 + 验收标准 |
| `产出示例/说明.md` | 本机 2026-10-25 真实跑一轮的结果：谁做的、被打回过几次、每版 SHA-256 |
| `产出示例/*.pptx / *.docx / *.xlsx` | 上面那轮跑出来的三份成品，可直接用 Office 打开逐字改 |
| `产出示例/质检报告/` | 那一轮的 8 份长报告原文（15 行 PASS/FAIL 输出、打回理由、复测比对） |
| `产出示例/派工回单/` | 那一轮的 12 步：`instruction-*` 派工原文 + `report-*` 干完回执，含 2 份 `status: FAILED` |
